# CPU66 timing experiment 20: select the maintenance write set before its tag match

Experiment17 balanced's worst path passes from a cache-maintenance tag compare through the valid/dirty write-set selector and a read of `lsw`. During E_M_SCAN2 the selected set is already known from the registered scan index; the tag match only decides whether any write/invalidation occurs.

The candidate selects `vp_set` unconditionally in that state and preserves every match, way mask, valid/dirty enable and value. WB fast writes are restricted to E_IDLE; the split store drains there before a scan may start; snooping freezes the engine. A simulation assertion at the scan's port selection also verifies that no earlier writer has enabled the port. When the match fails, the changed address is unused. No pipeline or engine state transition changes.

This prototype is experiment19 plus [scan-address.patch](perf/cpu66_20261022/timing20/scan-address.patch), still confined to scratch. All185 CPU cases and four adapters pass with exact experiment18 cycles, including split copyback, maintenance and snoop cases. No new register, cycle, array or timing exception is added. [Validation](perf/cpu66_20261022/timing20/validation.json). Fitting is required before any timing/area benefit can be claimed. No VRAM/DDR changes are included.

After all experiment17/18 flows and reports ended, the tested18,19 and20 patches were applied to the main timing branch. All CPU RTL/source-data files were byte-compared against the tested experiment20 scratch tree. The next paired fits keep balanced synthesis and seed38, comparing physical register duplication OFF versus ON. Both use the new stamp261023, matching the current day and reserving a distinct release stamp from the frozen261022 build; comparison with earlier placement results also includes that stamp change. The two new variants differ only in register duplication. The main QSF retains duplication OFF.

The fits completed and produced **byte-identical RBFs**: MD5 `d544c384215fa810494ba23df3ed84fd`,4,373,216 bytes. Physical register duplication ON has no effect in this flow, confirming the historical QSF note for the current CPU too. Both fit in **33,789 ALMs (80.6%)**,30,939 registers,489 M10Ks and38 DSPs. CPU setup **−1.652 ns / TNS −410.609 ns** still fails; SDRAM +0.444 ns, bus +1.230 ns and HDMI +0.388 ns pass. [Normal reports/hashes](perf/cpu66_20261022/timing20/fit/artifact.json), [duplication reports/hashes](perf/cpu66_20261022/timing20/fit-dup/artifact.json). Neither was deployed.

Compared with experiment18 balanced, logic grows446 ALMs and TNS worsens while worst slack improves only0.101 ns. This is a weak global tradeoff, not a timing-closed result. The actual worst path is FPSR pending-exception classification → EX full write qualification → AG operand selection → DC1 B. That last selection is overwritten by the later `exw_fw` broadcast when AG advances, making the prior experiment13 simplification relevant again alongside the separately tested index pre-read. No further comparisons of the ineffective duplication switch are planned.
