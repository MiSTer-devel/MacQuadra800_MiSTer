# CPU66 timing experiment 11: parallel stalls with circular queue

This compares experiment 10 with experiment 6's circular representation of the same two-slot micro-op FIFO. The old attempt predated the cache selector fix and regressed other paths. With that cache family now passing, this experiment measures whether the queue removes the late hold → wide FIFO head path that still limits experiment 8.

Two pointer bits select the same two storage banks. A pop moves only the read pointer; emit writes only the selected bank. There are no extra entries, wide banks or cycles. The existing FIFO observer compares all valid contents against the original queue every active clock. All **185 CPU cases and four adapters pass**, with exactly matching cycle counts to experiment 10. [Validation](perf/cpu66_20261022/timing11/validation.json), [queue model](perf/cpu66_20261022/timing6/fifo_model.py).

66/33/99 MHz, seed 38 and balanced synthesis remain fixed. Fit complete: **33,280 ALMs**, CPU setup **-1.898 ns**, CPU TNS **-184.885 ns**. SDRAM +0.537 ns, bus +0.601 ns, HDMI +0.349 ns and minimum hold +0.109 ns pass. [Reports and RBF hashes](perf/cpu66_20261022/timing11/fit/artifact.json). CPU timing still fails; this candidate is not hardware qualified. Neither this nor experiment 10 is promoted before the fitted area/setup/hold/crossing results are measured.

The circular queue costs 129 ALMs above experiment 10 (80 above the minimal 33 MHz core) and improves TNS from −370.294 ns to −184.885 ns. Its worst path is now EX condition/sign → divide-overflow kill → full front-file write qualification → redundant AG operand bypass → `dc1_a[5]`, 11 logic levels, with 78% of data delay in routing. An existing later AG→DC1 forwarding assignment overrides every case where that full bypass would contribute. Removing this unused earlier bypass is the next zero-state experiment. The four-clock DBcc compatibility setting will also be fitted for A/UX.
