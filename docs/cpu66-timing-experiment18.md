# CPU66 timing experiment 18: separate FPU branch data from commit qualification

Experiment16 speed's worst path traverses EX exception qualification, FPU branch gating, branch selection/misprediction and early redirect before registering return-stack restore valid. The branch's predicate and counter can be calculated independently of whether EX may commit it, as the FPU result data already is.

This candidate calculates `taken` from FC_COND/FC_DBCC, the latched instruction words, FPU condition codes and the counter. Hold and exception generation retain their original logic. The backend still qualifies early redirects with EX faults, exceptions, odd targets, serialization, flush and kill. No register, cycle or timing exception is added. Branch data outside a valid advancing nonexception uop is no longer forced to zero; it is not committed there. A simulation-only copy of the original gated branch decision is checked on every advancing valid nonexception FPU uop.

All **185 CPU cases and four adapters pass with exact experiment17 cycle counts**. An additional five bus configurations change the existing FPU test's signaling false branch (FBSF) into a signaling true branch (FBST), with unordered FPSR and BSUN enabled: the raw branch now says taken while BSUN must still win. They pass with exact baseline cycle counts. The full-run witness observes590 conditional FPU uops, six taken nonexception branches and one BSUN with raw taken, confirming the exception-suppression case is exercised. [Validation](perf/cpu66_20261022/timing18/validation.json).

The prototype lives only in scratch while experiment17 fits; main RTL remains frozen. The pinned source is experiment17 plus [branch-result.patch](perf/cpu66_20261022/timing18/branch-result.patch), applied with `git apply --unidiff-zero`. Builds use a composite archive with the tested fpif file substituted; the manifest identifies the base source/archive, patch and final file hashes. 66/33/99MHz, seed38, stamp261022 remain fixed. Actual area and all timing results decide retention; this is not yet a hardware-qualified build. An additional **25 cases with AP_FPU_PIPE=1 pass**, covering FPU operations, exceptions, frame save/restore, resume and the new signaling-true BSUN case under five bus configurations. This checks the hold qualification when the optional FPU pipeline is busy; the actual fit remains AP_FPU_PIPE=0. No VRAM/DDR changes are included.

Both fits completed. Balanced: **33,343 ALMs**, CPU **−1.753 ns / TNS −226.647 ns**, SDRAM +0.699 ns, bus +0.978 ns, HDMI +0.499 ns, minimum hold +0.203 ns. Speed: **33,314 ALMs**, CPU **−1.997 ns / TNS −238.966 ns**, SDRAM +0.320 ns, bus +0.864 ns, HDMI +0.152 ns, minimum hold +0.095 ns. [Balanced reports/hashes](perf/cpu66_20261022/timing18/fit/artifact.json), [speed reports/hashes](perf/cpu66_20261022/timing18/fit-speed/artifact.json). Neither closes CPU setup or has been deployed. Related-clock paths and holds pass.

The FPU-gated early branch is no longer the worst path. Balanced is limited by the micro-op queue read pointer (fanout323), register-file selection, index scaling and AG capture. Speed is limited by FPU exception qualification into WB exception-address selection. These results support testing targeted register duplication for routing pressure while measuring its area cost; no pipeline stage is proposed for that comparison.
